## Why Migrate?

At Hackmetrix, we had a growing codebase built with Vue.js 2 that was becoming harder to maintain. The ecosystem was shifting, and many libraries we wanted to adopt were React-first. The decision wasn't taken lightly -- we had a production application serving paying customers.

## The Strategy: Progressive Migration

We didn't rewrite everything. Instead, we adopted a **strangler fig pattern**:

1. Wrapped the existing Vue app inside a React shell
2. Used **Webpack Module Federation** to share dependencies between both frameworks
3. Each new feature was built in React; existing Vue components stayed in place
4. Over time, Vue components were replaced one by one

This approach let us ship continuously without a "big bang" migration that would freeze feature development for months.

## Challenges We Faced

State management was the biggest headache. We used Vuex in the Vue world and React Context + hooks in React. Sharing state between both frameworks required careful coordination.

We solved this by:

- Keeping global state in a framework-agnostic store (a simple event emitter + local storage)
- Using custom elements (web components) as the bridge between Vue and React components
- Extensive end-to-end tests to catch regressions during the transition

## Results

After 5 months of progressive migration:

- 70% of the frontend codebase was in React
- Bundle size decreased by ~25% due to tree-shaking
- Developer satisfaction improved significantly
- Zero production incidents caused by the migration

## Key Takeaways

- Progressive migration over rewrites, always
- Invest in testing infrastructure before starting the migration
- Framework-agnostic patterns (custom events, web components) are your friends
